This release makes the Brittany AI Tour Guide observable in production and provides
persisted monitoring for RAG quality, reliability, feedback, evaluation usage, and LLM
costs.

### Highlights

- Added persisted RAG execution records with answers, success status, errors, latency,
  sources, citations, model metadata, tokens, and traces.
- Added persisted user feedback linked to individual RAG requests.
- Added schema-separated LLM usage tracking for operational calls and offline
  evaluations.
- Added model pricing tables with input, cached-input, and output token costs.
- Added validation that raises an explicit error when a billable model has no configured
  pricing.
- Added backward-compatible database migrations for pricing, usage, and evaluation run
  references.
- Added curated evaluation cost reporting through
  `evaluation.llm_evaluation_cost_summary`.
- Added curated operational cost reporting through
  `public.llm_operational_cost_summary`.
- Added USD fallback handling for zero-cost evaluation and fixture runs.
- Added persisted Search, RAG, and Judge evaluation dashboards.
- Added a Production Quality dashboard for request volume, success rate, latency,
  errors, search modes, and user feedback.
- Added a Production Costs dashboard for LLM costs, call types, token usage, and
  model-level spending.
- Added stacked-chart-ready queries with zero-valued categories for missing error and
  judge data.
- Added Metabase dashboard export and restore workflows.
- Added preconfigured Metabase dashboards to the Docker image.
- Improved database initialization and recovery when the `public` schema is recreated.
- Updated Make commands to start PostgreSQL services in detached mode by default.
- Added `DEBUG=1` support for verbose Docker Compose diagnostics.
- Updated the roadmap with the completed Monitoring milestone and this release.

### Monitoring baseline

The application now exposes separate operational and evaluation views. Production
dashboards measure request quality, reliability, feedback, latency, model usage, and
cost without mixing those signals with offline RAG or judge evaluations.

Fixture-backed evaluations remain visible as zero-cost runs, while real billable models
must have pricing configured before their usage can be persisted.

Further work includes prompt and model comparison for LLM evaluation, reranking, query
rewriting, public screenshots, CI delivery automation, and optional cloud deployment.
